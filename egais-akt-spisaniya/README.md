# Помощник акта списания ЕГАИС (1С)

Внешняя обработка 1С для автоматизации подготовки акта списания ЕГАИС: диагностика справок 2, автоматическое исправление типовых проблем с акцизными марками и корректное заполнение акта.

**Статус:** MVP, черновик. Код не проверен на базе заказчика — места, требующие сверки с конфигурацией, помечены `// УТОЧНИТЬ`.

## Что автоматизируется

| Кейс | Проблема | Документ |
|---|---|---|
| 1 | Пустая или неверная номенклатура у марки, ТТН без номенклатуры, расхождение крепости | [01](docs/01_keis1_nomenklatura_na_marke.md), [02](docs/02_keis1_ttn_bez_nomenklatury_krepost.md) |
| 2 | Неверные статусы марок (марок «в наличии» меньше, чем требует ЕГАИС) | [03](docs/03_keis2_statusy_marok.md) |
| 3 | Нет соответствия номенклатуры с алкогольной продукцией | [04](docs/04_keis3_sootvetstvie_nomenklatury.md) |
| 4 | По справке 2 нет марок, очередь запросов в ЕГАИС | [05](docs/05_keis4_net_marok_ochered.md) |
| — | Заполнение акта списания, баг «7 строк» | [06](docs/06_akt_spisaniya_dobavlenie_marok.md) |

Каркас обработки (адаптер метаданных, диагностика, план изменений, журнал) — [00](docs/00_karkas.md). Сводка по сборке, защитным флажкам и вопросам — [docs/README.md](docs/README.md).

## Как собрать

1. Демо-база 1С:Розница 2.3 или **копия** рабочей базы с отключённым обменом с УТМ.
2. Конфигуратор → создать внешнюю обработку по [docs/STRUCTURE.md](docs/STRUCTURE.md).
3. Вставить `src/ObjectModule.bsl` в модуль объекта, `src/FormModule.bsl` — в модуль формы.
4. Синтаксис-контроль → запуск в 1С:Предприятие → «Проверить адаптер» → поправить `ИменаОбъектов()`.

Готовые `.epf` в репозиторий не коммитим — прикладываем к GitHub Releases.

## Правила работы

- Изменения кода — в `src/*.bsl`. После правок в Конфигураторе модули копируются обратно в `src/` перед коммитом.
- Никаких данных заказчика в репозитории: выгрузок баз (`.dt`, `.1CD`), реальных марок, справок, скриншотов учёта.
- Тесты — только на копии базы. На рабочей базе допустим только режим диагностики.
