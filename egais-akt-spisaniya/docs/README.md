# Помощник акта списания ЕГАИС — MVP

Внешняя обработка 1С для автоматизации подготовки акта списания ЕГАИС: диагностика справок 2, исправление типовых проблем (кейсы 1–4) и корректное заполнение акта.

Статус: черновик для 1С-разработчика. Конфигурация и версия заказчика неизвестны — все места, где имена взяты из типовых конфигураций «по памяти», помечены `// УТОЧНИТЬ`. Код не проверен на реальной базе.

## Порядок сборки

1. Развернуть **демо-базу 1С:Розница 2.3** (до получения базы заказчика) или копию базы заказчика с **отключённым обменом с УТМ**.
2. Создать внешнюю обработку `ПомощникАктаЕГАИС` по документу 00, нажать «Проверить адаптер», поправить `ИменаОбъектов()`.
3. Подключать документы по порядку 01 → 06. В каждом документе есть разделы:
   - «Изменения в адаптере» — ключи, которые нужно добавить в `ИменаОбъектов()`;
   - «Изменения в реквизитах обработки» — новые реквизиты и табличные части;
   - код, заменяющий заглушки каркаса, и ветки диспетчера;
   - изменения формы;
   - тест-кейсы и вопросы.
4. После каждого документа — прогон его тест-кейсов на подготовленных «поломках».
5. Версии на MVP: копии `.epf` с номером (`ПомощникАктаЕГАИС_v0.1.epf`, …) и короткий список изменений.

## Итоговый диспетчер действий

После подключения всех документов процедура `ВыполнитьДействие` каркаса выглядит так:

```bsl
Процедура ВыполнитьДействие(Строка)
	
	ПараметрыДействия = Неопределено;
	Если ЗначениеЗаполнено(Строка.ПараметрыСтрокой) Тогда
		ПараметрыДействия = ЗначениеИзСтрокиВнутр(Строка.ПараметрыСтрокой);
	КонецЕсли;
	
	Если Строка.ТипДействия = "ПерепроведениеДокумента" Тогда      // 01
		ДействиеПерепровестиДокумент(Строка.Объект, ПараметрыДействия);
		
	ИначеЕсли Строка.ТипДействия = "ЗаполнениеНоменклатуры" Тогда  // 01, 02
		ДействиеЗаполнитьНоменклатуруТТН(ПараметрыДействия);
		
	ИначеЕсли Строка.ТипДействия = "ИзменениеКрепости" Тогда       // 02
		ДействиеИзменитьКрепость(ПараметрыДействия);
		
	ИначеЕсли Строка.ТипДействия = "СменаСтатуса" Тогда            // 03
		ДействиеСменитьСтатус(ПараметрыДействия);
		
	ИначеЕсли Строка.ТипДействия = "СозданиеСоответствия" Тогда    // 04
		ДействиеСоздатьСоответствие(ПараметрыДействия);
		
	ИначеЕсли Строка.ТипДействия = "ЗапросМарок" Тогда             // 05
		ДействиеПоставитьВОчередь(ПараметрыДействия);
		
	ИначеЕсли Строка.ТипДействия = "ПерепривязкаМарки" Тогда       // 05
		ДействиеПерепривязатьМарку(ПараметрыДействия);
		
	ИначеЕсли Строка.ТипДействия = "ЗаполнениеСтрокиАкта" Тогда    // 06
		ДействиеЗаполнитьСтрокуАкта(ПараметрыДействия);
		
	ИначеЕсли Строка.ТипДействия = "Информация" Тогда
		ВызватьИсключение "Информационная строка: применять нечего, нужна ручная проверка.";
		
	Иначе
		ВызватьИсключение "Неизвестный тип действия: " + Строка.ТипДействия;
	КонецЕсли;
	
КонецПроцедуры
```

И `СформироватьПлан`:

```bsl
Процедура СформироватьПлан() Экспорт
	ПланИзменений.Очистить();
	СформироватьПланКейс1();   // 01, 02
	СформироватьПланКейс2();   // 03
	СформироватьПланКейс3();   // 04
	СформироватьПланКейс4();   // 05
	ДобавитьПланПоКрепости();  // 02
	СформироватьПланАкта();    // 06
КонецПроцедуры
```

## Типовой сценарий пользователя

1. Выбрать акт → **«Диагностика»**: справки разложены по кейсам, подсвечены цветом.
2. **«Сформировать план»** → проверить строки, отметить нужные → **«Применить подтверждённые»**. После применения диагностика запускается повторно.
3. Для кейса 2: на странице «Сверка марок» состояния обычно уже заполнены из полученных остатков. Что не заполнено — добирают резервом: кеш УТМ или check1, причём с check1 можно вставить в «Последнее движение» текст ответа, и состояние выведется само. Дальше снова «Сформировать план» → применить. Если марок нет в 1С — помогает только полный запрос остатков, запроса по одной справке в ЕГАИС нет.
4. Для кейса 4: справки уходят в очередь запросов, форма обрабатывает её сама, пока открыта.
5. Когда справки «Готово» — в плане появляются строки «ЗаполнениеСтрокиАкта» → применить → **«Проверить акт»**.
6. Провести и отправить акт — вручную, как сейчас.

## Главные вопросы (сводно)

Закрыто ответами заказчика (кейс 1, 06.10):

- Перепроведение подтверждённой ТТН в ЕГАИС ничего не отправляет; у неподтверждённой — может отправить акт, поэтому проводим только подтверждённые.
- Основание марки — последнее место фиксации (ТТН → чек → акт списания), поэтому ТТН ищем по справке 2.
- Номенклатура хранится в самой акцизной марке (видна через функции технического специалиста); справка 2 уникальна, номенклатура — нет и годится для всех справок одной позиции.
- Из «основание = чек» нельзя делать вывод «марка продана»: неудачная попытка продажи тоже ставит чек.

Открыто:

1. Конфигурация и версия 1С заказчика, версия УТМ.
2. Как технически связаны ТТН и поступление / перемещение: реквизит в ТТН, ввод на основании или регистр (вопрос задан, ответа нет).
3. Что означает «<Несколько позиций (N)>» в строке ТТН и как такую строку правят.
4. Какая процедура формы ТТН дозаполняет номенклатуру при открытии (`*`)?
5. Структура акта: связь строк товаров и марок, единицы количества.
6. Что значит «брать марки с сервера» и подтверждается ли гипотеза о новых справках после обнуления?
7. Регламент для «чужих» марок и марок, которых нет в ЕГАИС.
8. Менять ли крепость номенклатуры автоматически.
9. Соответствия номенклатуры можно создавать на точке или только на сервере (кейс 3)? Если только на сервере — на точке обработка только собирает список.

Подробные вопросы — в конце каждого документа.
