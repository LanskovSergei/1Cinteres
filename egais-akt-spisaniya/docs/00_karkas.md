# Шаг 0. Общий каркас обработки «Помощник акта списания ЕГАИС»

Версия документа: 0.1
Статус: черновик для 1С-разработчика. Конфигурация и версия заказчика пока неизвестны.

---

## 1. Назначение

Каркас — это основа, к которой по очереди подключаются кейсы 1–4 и заполнение акта. Он отвечает за:

- выбор акта списания ЕГАИС;
- диагностику всех справок 2 акта и классификацию по кейсам;
- план изменений с предпросмотром и подтверждением;
- применение изменений в транзакциях с журналом;
- проверку, что все нужные объекты конфигурации существуют.

Сами исправления по кейсам в каркасе оставлены заглушками — они реализуются в следующих документах (01–06).

---

## 2. Главный принцип: адаптер метаданных

Конфигурация заказчика неизвестна, поэтому **все имена объектов и реквизитов собраны в одной функции** `ИменаОбъектов()`. Весь остальной код использует только логические имена.

Когда станет известна конфигурация:

1. Разработчик правит только функции `ИменаОбъектов()` и `СоответствиеСтатусов()`.
2. Нажимает в форме кнопку «Проверить адаптер» — обработка сама проверит, что все объекты, реквизиты, табличные части и значения перечислений существуют, и выведет список расхождений.
3. Остальной код менять не нужно (в идеале).

Все места, где имена взяты «по памяти» из типовых конфигураций, помечены `// УТОЧНИТЬ`.

### Как подготовиться заранее, не зная конфигурацию заказчика

Разрабатывать и отлаживать на **демо-базе 1С:Розница 2.3** (поставляется вместе с дистрибутивом, в ней есть объекты ЕГАИС). Это самая вероятная конфигурация для розничной сети с алкоголем. Когда появится база заказчика — прогоняем «Проверить адаптер» и правим имена.

## 3. Структура обработки

### 3.1. Реквизиты обработки

| Имя | Тип | Назначение |
|---|---|---|
| Акт | ДокументСсылка.АктСписанияЕГАИС `// УТОЧНИТЬ` | Акт списания, по которому работаем |
| ЛимитПакета | Число (5,0), по умолчанию 50 | Сколько изменений применять за один запуск |

### 3.2. Табличная часть `Результаты` (диагностика)

| Имя | Тип | Назначение |
|---|---|---|
| Справка2 | СправочникСсылка.СправкиБЕГАИС `// УТОЧНИТЬ` | Справка 2 из строки акта |
| ТребуетсяМарок | Число (10,0) | Количество по строке акта |
| ВсегоМарок | Число (10,0) | Всего марок по справке в 1С |
| ВНаличии | Число (10,0) | Марок в статусе «В наличии» |
| БезАлкопродукции | Число (10,0) | Марок с пустой алкопродукцией (кейс 1) |
| НеверныхНоменклатур | Число (10,0) | Марок с неверной номенклатурой (кейс 1, заполняется в документе 01) |
| БезСоответствия | Число (10,0) | Марок, у алкопродукции которых нет соответствия номенклатуры (кейс 3) |
| Кейс | Число (1,0) | 0 — готово, 1–4 — номер кейса |
| Статус | Строка (20) | «Готово», «Проблема», «Предупреждение», «Исправлено» |
| Описание | Строка (0) | Пояснение для пользователя |

### 3.3. Табличная часть `ПланИзменений` (предпросмотр)

| Имя | Тип | Назначение |
|---|---|---|
| Подтверждено | Булево | Пользователь согласен применить |
| Кейс | Число (1,0) | Из какого кейса изменение |
| Справка2 | СправочникСсылка.СправкиБЕГАИС `// УТОЧНИТЬ` | Справка, к которой относится |
| ТипДействия | Строка (50) | «СменаСтатуса», «ПерепроведениеДокумента», «ЗаполнениеНоменклатуры», «СозданиеСоответствия», «ЗапросМарок» |
| Объект | ЛюбаяСсылка | Что меняем (марка, ТТН, номенклатура) |
| Было | Строка (0) | Текущее значение (для человека) |
| Стало | Строка (0) | Новое значение (для человека) |
| Основание | Строка (0) | Почему меняем: «нет чека», «ответ УТМ от …» и т.п. |
| ПараметрыСтрокой | Строка (0) | Параметры действия, сериализованные через `ЗначениеВСтрокуВнутр` |
| Выполнено | Булево | Применено успешно |
| Результат | Строка (0) | «OK» или текст ошибки |

### 3.4. Форма

- Поле «Акт списания» и кнопки: **«Проверить адаптер»**, **«Диагностика»**, **«Сформировать план»**, **«Применить подтверждённые»**.
- Страница «Диагностика»: таблица `Объект.Результаты` с цветовой подсветкой по кейсам.
- Страница «План изменений»: таблица `Объект.ПланИзменений` с флажками, кнопки «Отметить все» / «Снять все».
- Страница «Журнал»: результат последнего применения (фильтр `ПланИзменений` по `Выполнено`), при необходимости — ссылка на журнал регистрации.

Цвета строк диагностики:

| Кейс | Цвет |
|---|---|
| 0 | Бледно-зелёный |
| 1 | Светло-оранжевый |
| 2 | Светло-жёлтый |
| 3 | Светло-голубой |
| 4 | Светло-красный |

## 5a. Контроли перед диагностикой (версия 0.1.4)

**Битые ссылки «<Объект не найден> (223:…)».** Ссылка есть, а объекта в базе нет. По словам заказчика, в основании марки это не страшно, а битая алкопродукция или номенклатура лечится только на сервере с последующей синхронизацией на точку. Поэтому такие справки:
- считаются в колонке `БитыеСсылки`;
- получают статус **«Ручное решение»** и не попадают ни в один кейс — автоматических исправлений по ним нет;
- выводятся в плане отдельной информационной строкой.

**Уникальность справки 2.** В базе точки справка уникальна, но одна и та же справка может быть у разных магазинов. Если в базе нашлись марки нескольких организаций ЕГАИС по одной справке (значит, работаем в главной базе), диагностика останавливается с сообщением: запускать нужно в базе магазина или добавить отбор по организации. Контроль включается, когда в адаптере задан `МаркаОрганизация`.

**Какой акт брать.** По схеме заказчика после инвентаризации формируется несколько актов списания, нужен **второй сверху по дате инвентаризации**. Пока акт выбирает пользователь; автоматический выбор — после уточнения, чем отличаются эти акты.

### К 1С-разработчику (проверить на демо-базе / базе заказчика)

1. Акцизные марки — справочник или регистр сведений? Если регистр, проверить, что `КОЛИЧЕСТВО(Марки.#МаркаКод#)` и соединения работают корректно.
2. В акте списания Справка 2 — ссылка на справочник или строка с номером FB-…? От этого зависит соединение в запросе диагностики.
3. Марки в акте лежат в отдельной табличной части или внутри строк товаров? Как они связаны со строкой (ключ связи, идентификатор строки)?
4. Где хранится статус марки: реквизит, независимый регистр или движения документов?
5. Отправляет ли перепроведение входящей ТТН что-то в ЕГАИС? До ответа действие «ПерепроведениеДокумента» на реальных данных не запускать.
6. Будет ли обработка подключаться через «Дополнительные отчёты и обработки» (с безопасным режимом) или открываться через «Файл → Открыть»?

### К заказчику

1. Конфигурация и версия 1С, версия платформы.
2. Копия базы для разработки и тестов (с отключённым обменом с УТМ).
3. 5–10 реальных актов с проблемными справками по каждому кейсу.
4. Кто будет пользоваться обработкой (роль, права) и кто подтверждает изменения.
