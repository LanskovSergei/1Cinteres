# 04. Кейс 3: номенклатура не сопоставлена с алкогольной продукцией

Версия: 0.3 — ответы заказчика от 21.09 + скрины ручного процесса.
Код: `src/ObjectModule.bsl` (v0.1.8), область `Кейс3_СоответствиеНоменклатуры`.

> **Что видно на скринах и что сделано в 0.1.8.**
> Ручной путь: акт (пустая номенклатура) → акцизная марка → карточка алкопродукции («Сопоставлено в ИБ») → «Соответствие номенклатуры ЕГАИС» → «Создать» → вставить **код** номенклатуры.
> - В плане пишем код и артикул, не только наименование.
> - Если на карточке алкопродукции есть реквизит «Сопоставлено в ИБ», это кандидат с оценкой 95. Имя реквизита в адаптере `АлкопродукцияСопоставленоВИБ` — по умолчанию пустое: в части конфигураций это не поле, а список из того же регистра.
> - При записи регистра выставляем период, если регистр периодический; характеристику, упаковку и идентификатор упаковки пишем только если поля есть. **Справку 2 не заполняем** — так сказал заказчик 21.09, хотя в форме поле есть.

---

## 1. Задача

У алкопродукции ЕГАИС нет связи с номенклатурой 1С. Без этой связки нельзя оформить поступление, а марки остаются красными в акте списания.

Ручной процесс сейчас: марка → «Алкогольная продукция» → «Сопоставление в ИБ» → «Соответствие номенклатуры ЕГАИС» → «Создать» → указать номенклатуру (код берут из акцизной марки) → «Записать и закрыть».

---

## 2. Правила (подтверждены заказчиком)

| Вопрос | Ответ заказчика | Что это значит в коде |
|---|---|---|
| Уровень записи | Номенклатура привязывается к алкопродукции; справка 2 — просто id для поиска | Создаём только **общую** запись «алкопродукция → номенклатура», справку 2 не заполняем |
| Откуда брать номенклатуру | Из акцизной марки (номенклатура видна в марке через «Функции технического специалиста») | Главный источник кандидатов — номенклатура в марках этой алкопродукции (+90) |
| Несколько номенклатур на одну АП | Допустимо, в идеале одна | Если у АП уже появилось другое соответствие — не ошибка, добавляем своё |
| Новая номенклатура | Только выбор из существующих; создание номенклатуры — только на сервере | Никогда не создаём номенклатуру. Нет кандидатов → ручное решение |
| Кто создаёт соответствия | Только администраторы | Проверка роли перед записью |
| Подтверждения | Не нужны, всё автоматически | Однозначное применяется само (строка плана сразу отмечена), неоднозначное — «Требует ручного решения» |

Важное уточнение из ответов по кейсу 1: **основание марки меняется** (ТТН → чек → акт списания, это «последнее место, где зафиксирована марка»). Поэтому ТТН ищем по справке 2 в строках ТТН, а не через основание марки.

---

## 3. Алгоритм

1. **Детект** (каркас): у марок справки есть алкопродукция без единой записи соответствия → кейс 3.
2. **Одна алкопродукция — одна строка плана**, даже если она встречается в нескольких справках акта.
3. **Кандидаты номенклатуры:**

| Источник | Баллы |
|---|---|
| «Сопоставлено в ИБ» на карточке алкопродукции (если реквизит задан) | 95 |
| Номенклатура в акцизных марках этой алкопродукции (любые справки) | 90 |
| Строки ТТН с этой алкопродукцией и заполненной номенклатурой | 80 |
| Номенклатура «родственной» АП: тот же вид, объём, крепость, производитель и похожее наименование (≥ 0,6) | 60 |
| Поиск по наименованию в справочнике номенклатуры (первые 20) | 0…40 |

   Жёсткий фильтр: вид продукции (и объём, если включена проверка) должен совпадать — водку с вином не сопоставим.

4. **Решение без подтверждений:**
   - лучший кандидат ≥ 60 и отрыв от второго ≥ 20 → строка «СозданиеСоответствия», **сразу отмечена**, применяется автоматически;
   - иначе → строка «Требует ручного решения» с тремя лучшими вариантами в пояснении, **не отмечена**. Администратор может выбрать номенклатуру кнопкой «Выбрать номенклатуру»;
   - кандидатов нет → «Требует ручного решения: подходящей номенклатуры не найдено (новую создают на сервере)».

   Пример неоднозначности: в марках одной АП встречаются две разные номенклатуры — обе получают по 90, отрыв 0, автомат не угадывает.

5. **Действие** (одна транзакция):
   1. Проверка: пользователь — администратор.
   2. Запись соответствия «алкопродукция → номенклатура», если такой пары ещё нет.
   3. Заполнение номенклатуры в марках этой АП по справкам акта, **где она пустая**. Непустую другую номенклатуру не трогаем — это кейс 1.
   4. Если включена настройка — перепроведение ТТН (найденных по справке 2) с дозаполнением.
6. После применения каркас повторяет диагностику.

---

## 4. Настройки и адаптер

| Что | Где | По умолчанию |
|---|---|---|
| `АлкопродукцияСопоставленоВИБ` | `ИменаОбъектов()` | пусто — УТОЧНИТЬ имя реквизита «Сопоставлено в ИБ», если это поле, а не список |
| `СоответствиеИдентификаторУпаковки`, `СоответствиеХарактеристика`, `СоответствиеУпаковка` | `ИменаОбъектов()` | имена полей формы «Создать»; пустое значение в адаптере — поле не пишем |
| `МаркаНоменклатура` | `ИменаОбъектов()` | `"Номенклатура"` — УТОЧНИТЬ имя реквизита марки |
| `НастройкаПослеСоответствия()` | модуль объекта | `"ЗаполнитьМарки"`; альтернатива `"ЗаполнитьМаркиИПерепровестиТТН"` |
| `ЭтоАдминистратор()` | модуль объекта | роли `ПолныеПрава`, `АдминистраторСистемы` — УТОЧНИТЬ |

Что достаточно сделать, чтобы марки перестали быть красными в акте (только заполнить номенклатуру в марках или ещё перепровести ТТН), проверяем на копии базы и выставляем настройку.

## 5. Тест-кейсы

| № | Подготовка | Ожидаемый результат |
|---|---|---|
| 1 | Удалить соответствие для АП, у марок которой (в других справках) есть номенклатура | Кандидат «номенклатура в марках», строка отмечена, после применения соответствие создано, в марках справки заполнена номенклатура |
| 2 | АП встречается в 3 справках акта | Одна строка «СозданиеСоответствия» |
| 3 | В марках АП две разные номенклатуры | «Требует ручного решения», в пояснении обе |
| 4 | Кандидатов нет | «Требует ручного решения: не найдено»; после выбора вручную — применяется |
| 5 | Кандидат-вино для АП-водки | Отфильтрован |
| 6 | Пользователь без роли администратора | Ошибка «только администраторы», остальные строки плана применяются |
| 7 | У марки уже стоит другая номенклатура | Номенклатура марки не меняется |
| 8 | Соответствие с той же номенклатурой создали вручную после формирования плана | Повторная запись не создаётся, ошибки нет |

## 6. Оставшиеся вопросы

**К 1С-разработчику (на копии базы):**
1. Имя реквизита номенклатуры в акцизной марке и можно ли его записывать программно.
2. Обязательные измерения регистра соответствий кроме алкопродукции и номенклатуры (характеристика, упаковка).
3. Хватает ли заполнения номенклатуры в марках, чтобы марка перестала быть красной в акте, или нужно перепроведение ТТН.
4. Имя роли администратора в конфигурации.

**К заказчику:**
1. Соответствия номенклатуры можно создавать **на точке** или, как и номенклатуру, только на сервере? Если только на сервере — кейс 3 на точке может только собрать список для ручного решения на сервере.
2. Где будет запускаться обработка: на точке или на главной базе?
