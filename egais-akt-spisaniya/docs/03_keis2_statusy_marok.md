# 03. Кейс 2: статусы акцизных марок

Версия: 0.1. Зависит от: 00, 01 (функция `СправкиКейса`), 05 (вариант B — ответ по регистру 3, необязательно).

---

## 1. Задача

Номенклатура в порядке, а справка красная: например, ЕГАИС требует 7 марок, а в 1С «В наличии» только 6. Значит, у какой-то марки неверный статус.

Ручной процесс: проверить марки на check1.fsrar.ru и **подставить статус под ЕГАИС**:
- в ЕГАИС «Списано чеком» / «Списано актом» → в 1С «Реализована»;
- бутылка не продана («На остатках по чеку возврата» и т.п.) → в 1С «В наличии»;
- «В резерве» в 1С меняется всегда, в зависимости от ЕГАИС.

По схеме, в идеале проверять **все** марки справки.

---

## 2. Ключевые моменты

**Как хранится статус.** Если статус — реквизит марки или независимый регистр, его можно перезаписать. Если он пишется движениями документов (чек, возврат, резерв), прямое исправление **перетрётся при перепроведении** этих документов. До ответа на этот вопрос действие смены статуса защищено флажком `РазрешитьСменуСтатусов`.

**Источник «правды ЕГАИС».** Три варианта, по убыванию предпочтения:

| Вариант | Источник | Скорость | Автоматизация |
|---|---|---|---|
| A | Кеш УТМ 4: числится ли марка на балансе | Мгновенно | Полная |
| B | Ответ ЕГАИС по регистру 3 для справки (очередь из документа 05) | Медленно | Полная |
| C | check1.fsrar.ru, капчу вводит человек | ~5 сек на марку | Полуавтомат |

Для A формат запроса и ответа УТМ нужно взять из открытого кода «Помощника ЕГАИС» (Инфостарт) или документации УТМ 4 — в коде это место помечено `УТОЧНИТЬ`. Автоматический обход капчи check1 не делаем.

**Внутренние проверки 1С** (без ЕГАИС) не меняют статус сами по себе — они подсвечивают подозрительные марки и задают порядок проверки.

## 3. Изменения в адаптере

Добавить в `ИменаОбъектов()`:

```bsl
	// Марки в чеках (для проверки «Реализована, но чека нет»). Пусто — проверка отключена.
	Имена.Вставить("ТаблицаМарокЧеков", "Документ.ЧекККМ.АкцизныеМарки"); // УТОЧНИТЬ
	Имена.Вставить("ЧекМаркаКод",       "КодМарки");                      // УТОЧНИТЬ: код строкой или ссылка на марку
```

Настройки УТМ (отдельная функция):

```bsl
Функция НастройкиУТМ() Экспорт

	Настройки.Вставить("Адрес", "localhost"); // УТОЧНИТЬ: адрес УТМ точки
	Настройки.Вставить("Порт", 8080);         // УТОЧНИТЬ
	// Путь проверки марки в кеше УТМ 4, {mark} заменяется кодом марки.
	// УТОЧНИТЬ по коду «Помощника ЕГАИС» / документации УТМ 4. Пусто — вариант A выключен.
	Настройки.Вставить("ПутьПроверкиМарки", "");
	Настройки.Вставить("Таймаут", 10);
```

Матрица правил (отдельная функция, чтобы менять без правки логики):

```bsl
// Какой статус ставить в 1С по состоянию марки в ЕГАИС.
// СостояниеЕГАИС: "НаБалансе", "Списана", "Чужая".
// НовыйСтатус пустой — не менять.

	М.Колонки.Добавить("СтатусВ1С");
	М.Колонки.Добавить("НовыйСтатус");

	ДобавитьПравило(М, "НаБалансе", "ВРезерве",                 "ВНаличии");
	ДобавитьПравило(М, "НаБалансе", "НаОстаткахПоЧекуВозврата", "ВНаличии");
	ДобавитьПравило(М, "Списана",   "ВНаличии",                 "Реализована");
	ДобавитьПравило(М, "Списана",   "ВРезерве",                 "Реализована");
	ДобавитьПравило(М, "Списана",   "НаОстаткахПоЧекуВозврата", "Реализована");

	Возврат М;
	
КонецФункции

Процедура ДобавитьПравило(М, СостояниеЕГАИС, СтатусВ1С, НовыйСтатус)

```

| Имя | Тип | По умолчанию | Назначение |
|---|---|---|---|
| РазрешитьСменуСтатусов | Булево | Ложь | Защита до выяснения, как хранится статус |

Табличная часть **`СверкаМарок`**:

| Имя | Тип | Назначение |
|---|---|---|
| Справка2 | СправочникСсылка.СправкиБЕГАИС `// УТОЧНИТЬ` | Справка |

| Подсказка | Строка (200) | Результат внутренних проверок, ошибки УТМ. Именно ограниченная длина: по колонке сортируем, строки неограниченной длины сортировать нельзя |

## 5. Алгоритм

1. **Диагностика** (каркас) относит справку к кейсу 2: `ВНаличии < ТребуетсяМарок`, проблем кейсов 1 и 3 нет.
2. **«Сформировать план»**: если `СверкаМарок` пуста — заполняется всеми марками справок кейса 2 с текущими статусами и внутренними проверками. Строк плана пока нет (нечем подтвердить).
3. Пользователь на странице «Сверка марок»:
   - нажимает **«Проверить по УТМ»** (вариант A) — заполняется `СостояниеЕГАИС` для всех марок;
   - или **«Взять ответ регистра 3»** (вариант B, если по справке пришёл ответ);
   - или для спорных марок **«Открыть check1»** и выбирает состояние вручную (вариант C).
4. **«Сформировать план»** ещё раз: для марок с заполненным `СостояниеЕГАИС` по матрице добавляются строки «СменаСтатуса».
5. Марки с «Реализована» без чека, по которым ЕГАИС не проверен, попадают в план с основанием «нет чека (без подтверждения ЕГАИС)» — только как предложение, не отмечены.
6. «Чужая» марка — строка «Информация», без изменений.
7. Применение → повторная диагностика каркаса.

Отдельно: если после исправлений «в наличии» больше, чем требуется, каркас покажет «Предупреждение».

### 6.5. План (заменить заглушку `СформироватьПланКейс2`)

```bsl
#Область Кейс2_План

Процедура СформироватьПланКейс2()
	
	Если СправкиКейса(2).Количество() = 0 Тогда
		Возврат;
	КонецЕсли;

		Если СтрокаСверки.СостояниеЕГАИС = "Чужая" Тогда
			ДобавитьВПлан(2, СтрокаСверки.Справка2, "Информация", СтрокаСверки.Марка, СтрокаСверки.КодМарки, "",
				"Марка числится у другой организации — ручной разбор, автоматически не меняем");
			Продолжить;
		КонецЕсли;
		
		Если ЗначениеЗаполнено(СтрокаСверки.СостояниеЕГАИС) Тогда
			
			Правила = Матрица.НайтиСтроки(Новый Структура("СостояниеЕГАИС, СтатусВ1С",
				СтрокаСверки.СостояниеЕГАИС, СтрокаСверки.СтатусВ1С));
			Если Правила.Количество() = 0 Или Не ЗначениеЗаполнено(Правила[0].НовыйСтатус) Тогда
				Продолжить; // статус уже соответствует ЕГАИС
			КонецЕсли;
			
			ДобавитьПланСменыСтатуса(СтрокаСверки, Правила[0].НовыйСтатус,
				СтрШаблон("ЕГАИС: %1 (%2)", СтрокаСверки.СостояниеЕГАИС, СтрокаСверки.Источник), Истина);
			
		ИначеЕсли СтрокаСверки.СтатусВ1С = "Реализована" И Не СтрокаСверки.ЕстьЧек
			И ЗначениеЗаполнено(ИменаОбъектов().ТаблицаМарокЧеков) Тогда
			
			ДобавитьПланСменыСтатуса(СтрокаСверки, "ВНаличии",
				"Нет чека с маркой (без подтверждения ЕГАИС) — лучше сначала проверить", Ложь);
			
		КонецЕсли;
		
	КонецЦикла;
	
КонецПроцедуры

Процедура ДобавитьПланСменыСтатуса(СтрокаСверки, НовыйСтатус, Основание, Отметить)
	
	ДобавитьВПлан(2, СтрокаСверки.Справка2, "СменаСтатуса", СтрокаСверки.Марка,
		СтрШаблон("%1: %2", СтрокаСверки.КодМарки, СтрокаСверки.СтатусВ1С),
		НовыйСтатус, Основание,
		Новый Структура("Марка, КодМарки, СтарыйСтатус, НовыйСтатус",
			СтрокаСверки.Марка, СтрокаСверки.КодМарки, СтрокаСверки.СтатусВ1С, НовыйСтатус));
	
	ПланИзменений[ПланИзменений.Количество() - 1].Подтверждено = Отметить;
	
КонецПроцедуры

#КонецОбласти
```

### 6.6. Действие

```bsl
#Область Кейс2_Действие

// Параметры: Марка, КодМарки, СтарыйСтатус, НовыйСтатус (логические статусы).
Процедура ДействиеСменитьСтатус(П)
	
	Если Не РазрешитьСменуСтатусов Тогда
		ВызватьИсключение "Смена статусов запрещена настройкой «Разрешить смену статусов» "
			+ "(сначала выяснить, не перетрётся ли статус при перепроведении документов).";
	КонецЕсли;
	
	Имена = ИменаОбъектов();
	НовоеЗначение = ЗначениеСтатуса(П.НовыйСтатус);
	
	Если МаркиВСправочнике() Тогда
		
		МаркаОбъект = П.Марка.ПолучитьОбъект();
		МаркаОбъект.Заблокировать();
		ПроверитьСтарыйСтатус(МаркаОбъект[Имена.МаркаСтатус], П);
		МаркаОбъект[Имена.МаркаСтатус] = НовоеЗначение;
		МаркаОбъект.Записать();
		
	Иначе
		
		// Регистр сведений: отбор по коду марки. УТОЧНИТЬ состав измерений.
		ИмяРегистра = СтрЗаменить(Имена.ТаблицаМарок, "РегистрСведений.", "");
		Набор = РегистрыСведений[ИмяРегистра].СоздатьНаборЗаписей();
		Набор.Отбор[Имена.МаркаКод].Установить(П.КодМарки);
		Набор.Прочитать();
		
		Если Набор.Количество() <> 1 Тогда
			ВызватьИсключение СтрШаблон("Для марки %1 найдено записей: %2 (ожидалась 1).", П.КодМарки, Набор.Количество());
		КонецЕсли;
		
		ПроверитьСтарыйСтатус(Набор[0][Имена.МаркаСтатус], П);
		Набор[0][Имена.МаркаСтатус] = НовоеЗначение;
		Набор.Записать();
		
	КонецЕсли;
	
КонецПроцедуры

Процедура ПроверитьСтарыйСтатус(ТекущееЗначение, П)
	
	Если ЛогическийСтатус(ТекущееЗначение) <> П.СтарыйСтатус Тогда
		ВызватьИсключение "Статус марки изменился с момента формирования плана. Сформируйте план заново.";
	КонецЕсли;
	
КонецПроцедуры

#КонецОбласти
```

## 9. Вопросы

**К заказчику:**
1. Полная матрица «состояние в ЕГАИС / check1 → статус в 1С». Какие состояния показывает check1 и какие статусы есть в 1С? Есть ли статусы, которые трогать нельзя?
2. Что делать с «чужими» марками (числятся у другой организации)? Кто это разбирает?
3. «В идеале проверить все марки» — сверять все марки справки или только при недостаче?
4. Версия УТМ на точках (для варианта A нужен УТМ 4). Доступен ли УТМ с сервера 1С?

**К 1С-разработчику:**
1. **Как хранится статус марки** (реквизит, независимый регистр, движения документов)? Не перетрётся ли смена статуса при перепроведении чеков? От ответа зависит, можно ли включать `РазрешитьСменуСтатусов`.
2. Откуда в акте «требуется N марок»: из строки акта или из остатков ЕГАИС?
3. Как в чеках хранятся марки (табличная часть, код строкой или ссылка)? Хранятся ли ответы УТМ по чекам?
4. Есть ли в конфигурации запрос по регистру 3 и куда пишется ответ (для варианта B)?
5. Формат запроса/ответа кеша УТМ 4 — взять из кода «Помощника ЕГАИС», если купим.
