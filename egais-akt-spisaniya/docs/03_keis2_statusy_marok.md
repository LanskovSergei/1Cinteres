# 03. Кейс 2: статусы акцизных марок

Версия: 0.3 — по ответам заказчика от 21–22.09.
Код: `src/ObjectModule.bsl` (v0.1.3), область `Кейс2_СтатусыМарок`, плюс изменения в диагностике, классификации и адаптере.

---

## 1. Задача

Статусы части марок в 1С не совпадают с ЕГАИС. Из-за этого марки не находятся в акте или ЕГАИС отклоняет отправленный акт с ошибкой «ШК не найден в системе». Если до отправки выставить всем маркам правильный статус, ошибки не будет.

---

## 2. Что известно от заказчика

| Тема | Ответ | В реализации |
|---|---|---|
| Статусы | В ЕГАИС два состояния: «В обороте» → в 1С «В наличии», «В архиве» → «Реализована». Другого статуса для списанных нет | Матрица из двух направлений. «В резерве» — необязательный статус, если есть в конфигурации |
| Откат статуса | Статус меняется только при продаже или списании | Автоматическая смена безопасна, включена по умолчанию |
| Что сверять | Все справки акта, даже зелёные | Кейс 2 — при любом расхождении с ЕГАИС, а не только при недостаче |
| Источник правды | Полученные остатки (документ показан в кейсе 4). Запрос только полный, по всем маркам точки | Читаем последний документ остатков по организации ЕГАИС акта |
| Актуальность | Остатки устаревают уже на следующий день (марки продаются), но акт по ним актуален и через год | Нет ограничения по возрасту остатков; вместо этого **если марка двигалась в 1С после даты остатков — верим 1С** |
| Количество в акте | 1С считает сама: остаток ЕГАИС минус отсканированные | Контроль «в акте N = на балансе минус отсканированные» |
| Отсканированные | Файл `.1ct`, сохраняют после инвентаризации | Кейс 5: загрузка файла, вычитание из списания |
| Есть в ЕГАИС, нет в 1С | Не только потеря при выгрузке базы — бывают очень старые марки; помогает только запрос марок по справке 2 | Справка автоматически ставится в очередь запросов (кейс 4) |

## 3. Логика

Для каждой справки 2 акта:

1. Берём марки справки из 1С (статус и **дата основания** — последнего документа, где зафиксирована марка).
2. Берём марки справки из **последних остатков по этой справке** и их дату. Если по справке данных нет, статусы не трогаем: по схеме заказчика остатки запрашиваются из первого регистра, а марки приходят ответом по справке 2, поэтому отсутствие справки в остатках не означает, что марок на балансе нет. Режим «полный снимок» включается настройкой, когда это подтвердится.
3. Для каждой марки:

| Условие | Действие |
|---|---|
| Дата основания марки позже даты остатков | Ничего: марка продана / списана / пришла после остатков, верим 1С |
| На балансе («В обороте»), в 1С «Реализована» или «В резерве» | → «В наличии» |
| Не на балансе («В архиве»), в 1С «В наличии» или «В резерве» | → «Реализована» |
| На балансе, но марки нет в 1С | Справка — в очередь запросов марок по справке 2 (кейс 4) |
| Статус уже совпадает | Ничего |

4. **К списанию** = на балансе и не отсканирована при инвентаризации. Не совпадает с количеством в акте — информационная строка.

Изменения по данным остатков ЕГАИС применяются автоматически (строки плана сразу отмечены).

**Почему проверка даты основания важна.** Остатки запросили неделю назад, вчера марку пробили на кассе: в остатках она «В обороте», в 1С «Реализована». Без проверки мы вернули бы её в «В наличии». Дата основания (чек) позже даты остатков, поэтому марку не трогаем.

## 4. Реализация

### 4.1. Адаптер и настройки

| Ключ / функция | По умолчанию | Назначение |
|---|---|---|
| `ДокументОстатков` | `Документ.ОстаткиЕГАИС` | Документ полученных остатков — УТОЧНИТЬ по схеме (кейс 4) |
| `ОстаткиОрганизация` | `ОрганизацияЕГАИС` | Отбор по организации акта; пусто — без отбора |
| `ТЧОстатковМарки`, `ОстаткиСправка2`, `ОстаткиКодМарки` | `АкцизныеМарки`, `Справка2`, `КодМарки` | Табличная часть с марками в документе остатков |
| `НастройкаСрокАктуальностиОстатковЧасов()` | `0` | Без ограничения по возрасту |
| `НастройкаОстаткиПолныйСнимок()` | `Ложь` | Справки нет в остатках → считаем, что данных нет (безопасный режим). По схеме остатки берутся из первого регистра, где марок может не быть |
| `СоответствиеСтатусов()` | `ВНаличии`, `Реализована`, `ВРезерве` | «В резерве» необязательный |

Если документа остатков нет в конфигурации (имя не сверено), кейс 2 не падает, а работает без данных ЕГАИС: справки получают «Нет остатков ЕГАИС». «Проверить адаптер» покажет, что нужно поправить.

Код стал устойчив к отсутствию статуса в перечислении: такой статус пропускается, а не роняет диагностику.

### 4.2. Диагностика

- `ДополнитьДиагностикуКейс2` считает `НеВЕГАИС` и `ВЕГАИСНеВНаличии`, пропуская марки, которые двигались после даты остатков.
- Остатки читаются один раз за серверный вызов (кэш в переменной модуля).

### 4.3. Сверка и план

- В сверке новые колонки: `ДатаДвижения` (дата основания марки) и `ДатаОстатков`.
- Ручные источники остаются резервом: кеш УТМ 4 и check1 (в колонке «Состояние ЕГАИС» выбор «В обороте» / «В архиве»).
- Марки «есть в ЕГАИС, нет в 1С» → строка «ЗапросМарок» в очередь кейса 4, отмечена.

### 4.4. Что затронет другие части

- **Акт (документ 06):** в акт должны попадать марки «на балансе ЕГАИС минус отсканированные», а не все «В наличии». Доработаем при переходе к акту.
- **Кейс 4:** очередь пополняется и из кейса 2. Скорость зависит от ответа Дмитрия, можно ли запросить марки по конкретной справке.
- **Кейс 5:** заготовка загрузки файла инвентаризации — документ 07.

## 6. Открытые вопросы

**Ждём от заказчика:**
1. Можно ли запросить марки по конкретной справке (Дмитрий выясняет).
2. Пример файла `.1ct` (кейс 5).
3. Пример ошибки «ШК не найден» из протокола обмена.

**К 1С-разработчику (на копии базы):**
1. Имя документа полученных остатков, его табличной части с марками и полей (справка 2, код марки, организация). Это документ из кейса 4 на схеме.
2. Не попадают ли в этот документ частичные ответы (например, на запрос марок по справке). Если да — `НастройкаОстаткиПолныйСнимок()` = Ложь.
3. Основание марки — всегда документ (ТТН, чек, акт)? Используется его дата.
4. Совпадает ли формат кода марки в остатках, в справочнике марок и в файле инвентаризации.
5. Имена значений перечисления статусов («В наличии», «Реализована», «В резерве»).
