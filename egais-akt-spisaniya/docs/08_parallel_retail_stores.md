# Параллельная работа на многих розничных точках

## Задача

Около 200 магазинов на одинаковой конфигурации «Розница», у каждой точки — **своя информационная база** (или отдельное подключение к своей базе). Инвентаризацию и подготовку акта списания нужно вести часто; вручную обойти все точки нереально.

Обработка **«Помощник акта списания ЕГАИС»** рассчитана на то, что её можно **одновременно** открыть на разных компьютерах / в разных сеансах, каждый раз в **своей** базе точки.

## Как устроена изоляция данных (с версии 0.1.26)

Очередь запросов марок и данные инвентаризации (отсканированные марки, путь к файлу) сохраняются в **хранилище общих настроек** с ключом:

```text
ПомощникАктаЕГАИС_<ИмяИнформационнойБазы>[_<UUID организации ЕГАИС>]
```

- **Имя информационной базы** берётся из строки соединения — у разных точек ключи **не пересекаются**, даже если один и тот же пользователь 1С.
- Если в одной базе несколько организаций ЕГАИС и акты относятся к разным организациям, при **смене акта** на форме очередь и инвентаризация **перечитываются** для организации выбранного акта.

Старый ключ `ПомощникАктаЕГАИС` (без имени базы) при первом чтении **автоматически переносится** в новый ключ точки.

На форме (если добавлен элемент `НадписьКонтекстТочки`) и в заголовке окна отображаются имя базы и версия обработки. В журнале регистрации к комментариям плана добавлен идентификатор контекста точки.

## Рекомендуемая схема для ~200 точек

1. **Один .epf** (актуальной версии) — в общей папке или в типовом каталоге внешних обработок; на каждой точке подключают тот же файл или копию с той же версией (`Версия()` в модуле объекта).
2. **Параллельность «из коробки»**: каждый магазин работает в **своей** базе — отдельный сеанс 1С, отдельная очередь и инвентаризация. Конфликтов между точками нет.
3. **Внутри одной базы** не запускайте две копии обработки с **разными** актами разных организаций ЕГАИС в одном сеансе без понимания контекста: при смене акта данные переключаются. Для одной организации — один открытый экземпляр на пользователя достаточен.
4. **Инвентаризация**: сканирование / загрузка файла на точке → диагностика и план по акту → применение по типам (фильтр плана, «Следующий тип»). Очередь запросов марок дорабатывается фоновым обработчиком формы (раз в минуту).
5. **Центральный контроль** (по желанию): собирайте журнал регистрации с префиксом `ПомощникАктаЕГАИС` и идентификатором базы в комментариях; версию обработки смотрите в заголовке формы или через `КонтекстТочки()` из своих сценариев.

## Программный интерфейс (автоматизация)

Из внешнего кода или регламентного задания на **конкретной** базе:

```bsl
Обработка = ВнешниеОбработки.Создать("ПутьКПомощнику.epf");
Обработка.Акт = ...;
Контекст = Обработка.КонтекстТочки(); // ИмяБазы, Идентификатор, ОрганизацияЕГАИС, Представление, ВерсияОбработки
Обработка.ВыполнитьДиагностикуИСформироватьПлан();
// далее отметка строк плана и ПрименитьПлан() — по вашему сценарию
```

Каждый регламентный job должен выполняться **в сеансе той базы**, для которой предназначен (типовой паттерн: 200 баз — 200 заданий или обход списка строк подключения).

## Настройка формы в конфигураторе

| Элемент | Назначение |
|--------|------------|
| `НадписьКонтекстТочки` | Декорация / надпись, только заголовок (заполняется из модуля формы) |
| Поле `Объект.Акт` | Событие **При изменении** → `АктПриИзменении` |

Без `НадписьКонтекстТочки` контекст всё равно виден в **заголовке** окна формы.

## Ограничения

- Хранилище общих настроек привязано к **пользователю** 1С. На одной точке у разных пользователей — разные очереди инвентаризации (как и раньше). Для «одной точки — один ответственный» это нормально; для общей очереди на точку нужен отдельный механизм (регистр, общий каталог) — в MVP не реализован.
- Параллельная работа **не** объединяет 200 баз в одну: это **согласованная** модель «одна обработка — одна база — свой контекст», чтобы массово запускать её на всех точках без ручной синхронизации.
