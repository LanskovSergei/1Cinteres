# 07. Кейс 5 (DLC): марки, которые есть в магазине, не списываем

Версия: 0.2. Код: `src/ObjectModule.bsl` (v0.1.10), область `Кейс5_Инвентаризация`.

> Это не отдельный кейс диагностики, а фильтр для остальных шагов. На скрине: таблица «Акцизные марки» (статус 1С, статус ЕГАИС, справка, код марки). После инвентаризации файл содержит марки, которые физически в магазине. Перед попаданием в акт: если код есть в файле — не списываем.

---

## 1. Задача

После инвентаризации сохраняется файл с акцизными марками в магазине. Их списывать нельзя. Проверка нужна и в сверке статусов (кейс 2: «к списанию = на балансе минус отсканированные»), и при заполнении акта.

## 2. Что сделано

- Загрузка файла на странице «Инвентаризация»; список живёт между сеансами.
- Коды нормализуются (пробелы, символ GS1), чтобы файл и 1С совпали.
- Кейс 2 вычитает эти марки из «к списанию».
- **Акт:** `МаркиСправкиКСписанию` не берёт марки из файла. Количество в строке акта = сколько реально списываем, а не все «в наличии». Если после фильтра ноль — в акт не кладём, понятная ошибка.
- Проверка акта при заполнении одной справки не смотрит чужие строки (раньше чужой баг «7 строк» блокировал остальные).

Разбор файла без образца `.1ct` всё ещё эвристический: фрагменты от 68 символов (PDF417 / DataMatrix). На скрине коды начинаются с `19` или `32`.

## 3. Вопросы

**К заказчику:** пример файла `.1ct` (или выгрузка той таблицы со скрина). Из какой программы он. Один файл на магазин?

**К 1С-разработчику:** совпадает ли код в файле с `МаркаКод` в 1С (полный DataMatrix или обрезанный).
