# 09. Сервис сверки на сервере

Версия: 0.1 — интеграция обработки с `egais-mark-service`.

## Зачем

Правила сверки вынесены в отдельный сервис на сервере: там их проще менять, тестировать и замерять производительность. Обработка собирает данные из базы и отправляет их сервису, сервис возвращает решение.

Записывает изменения по-прежнему 1С. Сервис ничего в базе не меняет, поэтому его недоступность ничего не ломает: обработка считает всё сама, как раньше.

## Как подключено

| Что | Где |
|---|---|
| Адрес, порт, ключ | `НастройкиСервиса()` в модуле объекта |
| Обмен (HTTP, JSON, таймаут) | Область `СервисСверки` |
| Сравнение решений | Область `СервисСверкиПрименение` |
| Вызов | В конце `СформироватьПлан()` |

Сервис доступен только внутри VPN по адресу `10.8.0.1:8000`, запросы несут заголовок `X-API-Key`.

## Что делает сейчас

После формирования плана обработка прогоняет справки через сервис и **сравнивает** его решение со своим. Если они разошлись — в плане появляется информационная строка: сколько смен статуса предлагает обработка и сколько сервис, и совпадает ли «к списанию» со строкой акта.

Это режим опытной эксплуатации: ничего не применяется автоматически, но видно, одинаково ли считают оба движка. Когда накопится статистика и расхождений не останется, можно будет переключить обработку на решения сервиса.

## Настройка при внедрении

```bsl
Функция НастройкиСервиса() Экспорт
    Настройки = Новый Структура;
    Настройки.Вставить("Адрес", "10.8.0.1");  // пусто — обращение к сервису выключено
    Настройки.Вставить("Порт", 8000);
    Настройки.Вставить("Ключ", "...");        // X-API-Key, выдаётся отдельно
    Настройки.Вставить("Таймаут", 30);
    Возврат Настройки;
КонецФункции
```

Ключ в репозиторий не коммитим: он передаётся отдельно и прописывается в сборке при внедрении.

## Проверка

1. На ноутбуке с 1С поднят туннель WireGuard.
2. В модуле заполнен адрес и ключ.
3. «Диагностика» → «Сформировать план».
4. Если сервис недоступен, в плане появится строка «Сервис сверки недоступен — работаем на локальных правилах», остальное отработает как раньше.

## Вопросы

1. Когда переключать обработку с собственных правил на решения сервиса — после какого объёма проверок?
2. Нужно ли отправлять на сервис разбор файла инвентаризации и подбор номенклатуры, или пока достаточно сверки.
