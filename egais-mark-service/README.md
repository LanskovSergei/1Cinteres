# egais-mark-service

Микросервис проверки и сверки акцизных марок: принимает данные из 1С, применяет правила, которые раньше жили в модулях обработки «Помощник акта списания ЕГАИС», и возвращает решение.

Запись в базу 1С остаётся в 1С — сервис ничего не меняет сам, он только считает.

## Что внутри

| Модуль | Что делает |
|---|---|
| `app/engine/codes.py` | Нормализация кодов марок, разбор файла инвентаризации (`.1ct` и выгрузки из него) |
| `app/engine/statuses.py` | Матрица «состояние в ЕГАИС → статус в 1С», учёт даты последнего движения марки |
| `app/engine/reconcile.py` | Сверка трёх множеств (1С, ЕГАИС, отсканированные), расчёт «к списанию», подбор кандидатов по недостаче |
| `app/engine/classify.py` | Классификация справки по кейсам 1–4 |
| `app/engine/matching.py` | Похожесть наименований и оценка кандидатов номенклатуры |
| `app/logging_setup.py` | Структурные логи JSON, время обработки каждой марки |
| `app/main.py` | HTTP API |

Очередь запросов и прохождение CAPTCHA в этот сервис не входят.

## API

| Метод | Назначение |
|---|---|
| `GET /health` | Проверка живости |
| `POST /v1/reconcile` | Сверка по одной справке: марки 1С + данные ЕГАИС + отсканированные → смены статусов, «к списанию», замечания |
| `POST /v1/inventory/parse` | Разбор файла инвентаризации, возвращает нормализованные коды |
| `POST /v1/nomenclature/match` | Подбор номенклатуры по алкопродукции с оценкой кандидатов |
| `GET /v1/metrics/summary` | Сводка: сколько марок обработано, среднее время на марку, ошибки |

Полное описание — `/docs` (Swagger) после запуска.

## Запуск

```bash
cp .env.example .env
docker compose up -d --build
curl localhost:8000/health
```

Без Docker:
```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## Тесты

pip install -r requirements-dev.txt
